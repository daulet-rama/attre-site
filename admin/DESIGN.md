# Админка attré — устройство и договорённости

Админка для двух основательниц бренда (Дамира и Жанна): добавить, изменить, скрыть, удалить товар; цвета и фото;
цены и наличие; доставка и контакты. Люди не технические — интерфейс должен объяснять сам себя: по-русски,
крупно, с подсказками, с живым превью «как будет на сайте». ИИ у них нет.

## Как это работает

```
 телефон/ноутбук ──► админка (Railway, этот каталог admin/) ──► GitHub-репозиторий daulet-rama/attre-site
                                                                   data/*.json + media/products/*.jpg
                                                                        │ push в main
                                                                        ▼
                                                           GitHub Actions: python build.py → GitHub Pages (сайт)
```

* Сайт статический: `build.py` собирает `site/` из `data/` и `media/` (см. `core.py`, `themes/v4.py`).
* Админка НЕ хранит данные у себя: читает и пишет файлы репозитория. Каждое «Сохранить» = один коммит в `main`
  (данные + фото одним коммитом) → сайт пересобирается сам (≈2–3 мин). История и откат — в git.
* Хранилище фото — сам репозиторий (`media/products/`). Отдельное хранилище не нужно.
* Хостинг админки — Railway (Docker, корень сервиса `admin/`, watch paths `admin/**`).

## Стек и папки

* Python 3.12+, FastAPI, Uvicorn, httpx, Pillow + pillow-heif (фото с iPhone в HEIC), itsdangerous (подпись cookie).
  Без БД, без сборки фронтенда: фронт — чистый JS (ES-модули), HTML, CSS.
* `admin/app/` — пакет бэкенда: `main.py` (FastAPI, маршруты), `store.py` (хранилище: локальная папка+git или GitHub API),
  `catalog.py` (чтение/проверка/запись данных сайта), `images.py` (обработка фото), `auth.py` (вход),
  `passwords.py` (пароли, сменённые в админке: `.admin/users.json`), `config.py` (переменные окружения).
* `admin/static/` — фронт: `index.html`, `app.js` (+ при желании модули `js/*.js`), `app.css`, значки — inline SVG.
* `admin/tests/` — pytest (каталог, хранилище, API на LocalStore).
* `admin/Dockerfile`, `admin/requirements.txt`, `admin/railway.json`, `admin/.env.example`,
  `admin/README.md` (для разработчика: запуск, переменные, деплой), `admin/GUIDE.md` (для основательниц, по-русски).

## Данные (формат сайта — менять нельзя, только так)

Все JSON: `json.dumps(obj, ensure_ascii=False, indent=2) + "\n"`. Неизвестные поля при сохранении СОХРАНЯТЬ как были.
Тексты на трёх языках — объект `{"ru": "...", "kz": "...", "en": "..."}`; пустые `kz`/`en` сайт заменяет русским.

**Палитра** `data/colors.json` — 15 цветов заказчиц, порядок как в файле:
`black` чёрный, `blue` синий, `brown` коричневый, `beige` бежевый, `milky` молочный, `grey` серый, `red` красный,
`pink` розовый, `light-blue` голубой, `burgundy` бордовый, `green` зелёный, `yellow` жёлтый,
`leopard` леопардовый, `cow` коровий, `zebra` зебра. Элемент: `{key, hex|null, pattern?, name{ru,kz,en}}`
(у принтов `hex: null`, `pattern: leopard|cow|zebra` — кружочек рисуется узором). Админка палитру не меняет.

**Категории** `data/categories/<key>.json`: `{key, order, name{}, parent?}`. Сейчас: `bags` сумки, `acc` аксессуары
(родитель для двух других), `cardholder` кардхолдеры (parent `acc`), `charms` брелоки (parent `acc`).
В товаре — лист: `bags`, `cardholder`, `charms` (или новая категория). Удалять категорию с товарами нельзя.

**Материалы** `data/materials/<key>.json`: `{key, order, name{}}` — `leather` кожа, `suede` замша, `pony` ворс,
`textile` текстиль, `eco-leather` эко-кожа.

**Товар** `data/products/<slug>.json` (slug — латиница, цифры, дефис; это адрес страницы, после создания не меняется):

```json
{
  "id": "001",                       // артикул: 3 цифры, при создании = max+1
  "published": true,                 // «показывать на сайте»
  "order": 10,                       // порядок в каталоге (меньше — выше)
  "cat": "bags",
  "name": {"ru": "Altea", "kz": "Altea", "en": "Altea"},
  "type": {"ru": "сумка-ведро", "kz": "шелек сөмке", "en": "bucket bag"},
  "new": true, "popular": false, "soon": false,
  "price": 45000,                    // число или null («цена по запросу»)
  "stock": null,                     // null — просто «в наличии»; 0 — продано; 1 — «осталась одна»
  "desc":  {"ru": "", "kz": "", "en": ""},
  "strap": {"ru": "", "kz": "", "en": ""},
  "size": {"w": 30, "h": 25, "d": 12},   // см, числа или null
  "variants": [                       // цвета, минимум один; первый — основной (его фото в каталоге)
    {
      "color": "milky",               // ключ палитры
      "name": {"ru": "молочный", ...},// необязательно: свой оттенок («карамельный»); нет — название из палитры
      "material": "leather",          // необязательно
      "images": ["media/products/altea-milky-3fa2c1.jpg", "..."]   // 1–8 фото, первое — главное
    }
  ]
}
```

Старые поля `images`, `colors`, `color`, `materials` у товара без `variants` — наследие; админка при сохранении
переводит товар на `variants` (старые фото → один цвет) и убирает эти поля.
«Наличие» в форме: `stock == 0` → «продано»; `soon` → «скоро в наличии»; иначе «в наличии».

**Настройки** `data/settings.json`: `whatsapp` (цифры, 11 знаков, 7…), `instagram`, `pinterest` (ник), `email`,
`map_url` (ссылка 2ГИС), `delivery: {free_from, kz: [{price, name{}, days{}}]}`, `seller: {name, bin}` (новое: ИП/ТОО
и ИИН/БИН для подвала; пусто — строка в подвале не показывается).
Тексты в `data/i18n.json` → `t.<ключ>` (`{ru,kz,en}`): `address`, `hours` («Часы работы: 11:00–20:00»), `promo`
(чёрная полоса сверху), `dlv_world` (доставка по миру). Админка меняет только эти ключи, остальное не трогает.

## Хранилище (store.py)

```python
class Store:
    def head(self) -> str                                     # sha последнего коммита ветки
    def list(self, prefix: str) -> dict[str, str]             # путь → blob sha (файлы под prefix, рекурсивно)
    def read(self, path: str) -> bytes | None
    def blob_sha(self, path: str) -> str | None               # для защиты от одновременной правки
    def commit(self, changes: dict[str, bytes | None], message: str, author: str) -> str   # None = удалить; → sha коммита
```

* `LocalStore(LOCAL_REPO)`: файлы + `git` CLI (`git add/rm`, `git commit --author`), без push. Для разработки и тестов.
* `GitHubStore`: REST API — дерево `GET /repos/{r}/git/trees/{branch}?recursive=1`, содержимое через blobs,
  коммит через Git Data API (blobs → tree с base_tree, удаление = `sha: null` → commit → PATCH ref). Если ref ушёл
  вперёд (422/409) — перечитать head и повторить (до 3 раз). Кэш дерева и содержимого в памяти; сбрасывать после коммита.
* Все записи — под одним `asyncio.Lock`/`threading.Lock` (одна очередь на процесс).

## Фото (images.py)

* Принимаем JPEG, PNG, WEBP, HEIC/HEIF, до 30 МБ. Проверка — открыть Pillow (не верить расширению/MIME).
* Поворот по EXIF, прозрачность → белый фон, RGB, длинная сторона ≤ 2000, JPEG q88 progressive → в репозиторий.
* Превью для админки: 480px JPEG. Временные загрузки — `TMP_DIR/<upload_id>.jpg` (+ `_t.jpg`), живут 24 ч.
* Имя файла при сохранении товара: `media/products/<slug>-<color>-<6 hex>.jpg`. Фото, на которые больше не ссылается
  ни один товар, удаляются тем же коммитом.

## API (JSON; всё, кроме входа, требует сессию; ошибки — `{"error": "понятный текст по-русски", "field"?: "..."}`)

Без действующей сессии — 401 `{"error": "Войдите, чтобы продолжить."}`; если cookie наша, но пароль человека с тех пор
сменили или сбросили, — 401 `{"error": "Пароль сменили — войдите с новым паролем.", "reason": "password"}` (окно входа
говорит именно это). Пока файл сменённых паролей после запуска ни разу не прочитан (GitHub не ответил), запросы с
cookie и вход паролем получают 503.

| метод и путь | вход | выход |
|---|---|---|
| `POST /api/login` | `{name?, password}` | `{user}` + cookie; 401 «Пароль не подошёл. Проверьте раскладку (русская или английская) и большие буквы.»; 429 при переборе («Слишком много попыток входа. Попробуйте через N минут.») |
| `POST /api/logout` | | `{}` |
| `GET /api/session` | | `{user}` или 401 (с `reason: "password"`, если пароль сменили) |
| `POST /api/password` | `{current, new}` | `{}` + новая cookie этого устройства (прежние входы этого человека — недействительны); 400 с `field` `current` («Текущий пароль не подошёл. Проверьте раскладку (русская или английская) и большие буквы.», учитывается в счётчике попыток входа) или `new` (8–128 символов, без пробелов по краям и служебных символов, не равен имени и текущему); 429 при переборе («Слишком много неудачных попыток ввести пароль. Попробуйте через N минут.» — без «неверных»: счётчик общий на адрес и на всех, блокировку видит и та, кто не ошибалась); 401 `reason: "password"` — пока шёл запрос, пароль этого человека сменили на другом устройстве (не попытка подбора); 409 — файл паролей изменили в это же время. Пишет только `.admin/users.json` (коммит `Админка: смена пароля (Дамира)`, публикацию не ждём) |
| `GET /api/meta` | | `{palette[], categories[{key,name,parent,order,count,leaf}], materials[], types[{ru,kz,en}], site_url, users[]}` |
| `GET /api/products` | | `[{slug,id,name,cat,type,price,stock,soon,new,popular,published,order,colors[],thumb,photos}]` по `order` |
| `GET /api/products/{slug}` | | `{product, sha}` (product — как в файле + `"slug"`) |
| `POST /api/products` | `{product}` | `{slug, commit}` — создать (id, slug, order — сервер) |
| `PUT /api/products/{slug}` | `{product, sha}` | `{commit}`; 409 если файл изменился после `sha` |
| `DELETE /api/products/{slug}` | `?sha=` | `{commit}` — удаляет JSON и его фото |
| `POST /api/products/order` | `{slugs: [...]}` | `{commit}` — order = 10, 20, … одним коммитом |
| `POST /api/uploads` | multipart `file` | `{upload: "up_xxx", thumb: "/api/uploads/up_xxx", width, height}` |
| `GET /api/uploads/{id}` | | превью JPEG |
| `GET /api/media/{file}` | `?w=480` | превью фото из репозитория (кэш на диске) |
| `GET /api/settings` | | `{contacts{whatsapp,instagram,pinterest,email,map_url,address{},hours{}}, delivery{free_from,kz[],world{}}, promo{}, seller{name,bin}, sha}` |
| `PUT /api/settings` | то же + `sha` | `{commit}` |
| `GET /api/status` | | `{head, publish: {state: idle|queued|building|done|failed|unknown, commit, url, started, finished}, site_url}` |

* В `product.variants[].images` фронт присылает существующие пути `media/products/...` или `upload:up_xxx`.
* Проверки на сервере (и те же — на фронте до отправки): название (ru) 1–60 символов; категория существует и лист;
  хотя бы один цвет; у каждого цвета ключ палитры и 1–8 фото; цена — целое 0…10 000 000 или null; остаток — целое ≥ 0
  или null; размеры — числа 1…200 или null; тексты ≤ 2000. Дубли цвета в одном товаре допустимы (два оттенка коричневого),
  но тогда у второго нужно своё название оттенка.
* Статус публикации: GitHub Actions `GET /repos/{r}/actions/runs?branch=main&per_page=5` → прогон с `head_sha` = последний
  коммит админки; `queued`/`in_progress` → «публикуем», `completed+success` → «на сайте», иначе «ошибка».
  В `STORE=local` — `unknown`.
* Сообщение коммита по-русски: `Админка: «Altea» — сохранено (Дамира)`, `Админка: новый товар «Lucca» (Жанна)`,
  `Админка: удалён «Tokyo» (Дамира)`, `Админка: порядок товаров (Жанна)`, `Админка: доставка и контакты (Дамира)`.

## Безопасность

Cookie сессии: подписанная (itsdangerous), `HttpOnly`, `Secure` (кроме localhost), `SameSite=Lax`, 30 дней.
Пароли сравнивать `hmac.compare_digest`. Перебор: не больше 10 попыток входа за 15 минут с IP. Изменяющие запросы —
только JSON (кроме загрузки файла) и с заголовком `X-Requested-With: attre-admin` (защита от CSRF). Пути в API
(slug, имя файла, upload id) — строго по регулярным выражениям, никакого `..`. Размер запроса ограничен.
Токен GitHub — только в переменной окружения, в ответы и логи не попадает. Пароль, сменённый в админке, — в публичном
репозитории только как `HMAC-SHA256(pepper, scrypt(пароль, salt))`, pepper в репозиторий не попадает (README.md →
«Пароли и пользователи»); сами пароли нигде не логируются.

## Интерфейс (по-русски, для людей без технического опыта)

Общие правила: всё по-русски и просто («Сохранить и опубликовать», не «Commit»); крупные зоны нажатия (≥ 44px);
у каждого поля подпись и короткая подсказка серым («Пусто — на сайте будет «цена по запросу»»); обязательные поля
отмечены; ошибки — рядом с полем, красным, человеческим языком; нигде нет JSON, slug, sha. Стиль — как сайт: белый фон,
чёрный текст, тонкие линии, шрифт системный; акцент — голубой бренда `#a9c7e5` (выделение, фокус), опасное — красный.
Телефон — главный экран (вход по ссылке с телефона), ноутбук — две колонки.

1. **Вход.** Логотип attré, «Админка магазина», выбор имени (если пользователей несколько), пароль, «Войти».
2. **Шапка** (на всех экранах): «attré · админка», вкладки «Товары» / «Магазин и доставка», справа — «Открыть сайт ↗» и
   имя/выход (у имени — меню «Сменить пароль»; на телефоне всё это в меню под кружком с буквой). Под шапкой — **полоса публикации**: «Все изменения на сайте ✓» / «Публикуем на сайт… обычно 2–3 минуты»
   (с индикатором) / «Не получилось опубликовать — сообщите Даулету». Опрос `/api/status` раз в 5 с, пока идёт публикация.
3. **Товары.** Кнопка «+ Добавить товар». Поиск по названию/артикулу. Фильтры-чипы: Все · Сумки · Кардхолдеры · Брелоки ·
   Скрытые · Без цены · Скоро в наличии · Проданные. Сетка карточек: главное фото, название, цена или «цена по запросу»,
   кружочки цветов, бейджи «Скрыт», «Новинка», «Популярное», «Скоро», «Продано». Нажатие — редактор.
   «Изменить порядок» → режим перетаскивания (на телефоне — стрелки вверх/вниз у карточки) → «Сохранить порядок».
4. **Редактор товара.** Сверху: «← Все товары», название, переключатель «Показывать на сайте» (подсказка: «Выключите,
   чтобы спрятать товар, не удаляя»). Разделы:
   * **Основное**: Название*; Категория* (крупные чипы); Тип (поле с подсказками из существующих типов: сумка-ведро,
     тоут, хобо…; можно вписать свой); Артикул (показан, не редактируется).
   * **Цвета и фото***: блок на каждый цвет — выбор цвета из 15 кружочков с подписями (выбранный в кольце);
     «Свой оттенок (необязательно)» — например «карамельный»; Материал (чипы); фото: большая зона «Добавить фото»
     (несколько сразу, перетаскивание файлов на компьютере), миниатюры 3:4 с номером, «★ Главное» у первого,
     «Сделать главным», стрелки ←/→, «Удалить» (с подтверждением), индикатор загрузки, понятная ошибка для
     неподходящего файла. Подсказка: «Первое фото — главное: его видно в каталоге. Лучше вертикальные, светлый фон».
     «+ Добавить цвет»; «Удалить цвет» (подтверждение). Порядок цветов (первый — основной) — стрелки вверх/вниз.
   * **Цена и наличие**: Цена, ₸ (подсказка про «цена по запросу»; на телефоне — цифровая клавиатура); Наличие — три
     крупные кнопки: «В наличии» / «Скоро в наличии» / «Продано»; Остаток, шт. (необязательно; «если 1 — на сайте
     «осталась одна»); Метки: «Новинка» (в блоке новинок на главной), «Популярное».
   * **Описание и размеры**: Описание; Размер: ширина × высота × глубина, см (три поля в ряд); Ремень и ручки.
     Свёрнутый блок «Казахский и английский (необязательно)» — те же тексты на қаз/eng + тип; пусто — покажется русский.
   * Внизу липкая панель: «Сохранить и опубликовать» (главная, чёрная), «Отмена». В конце формы — «Удалить товар»
     (красная, подтверждение «Удалить «Altea» навсегда? Фото тоже удалятся. Можно вместо этого просто скрыть»).
   * **Превью «Так будет на сайте»**: на ноутбуке — справа, липкое; на телефоне — кнопка «Посмотреть, как на сайте»
     открывает лист. Показывает карточку каталога (фото основного цвета 3:4, кружочки — нажатие меняет фото, бейдж,
     название, тип, цена) и блок товара («цвет: молочный», кружочки, кнопка «в корзину»). Обновляется сразу при вводе.
   * Несохранённые изменения: предупреждение при уходе со страницы и при «← Все товары».
   * После сохранения: «Сохранено. Публикуем на сайт…» и ссылка «Открыть товар на сайте» (когда опубликовано).
   * Новый товар: тот же редактор, по умолчанию один пустой цвет и «Показывать на сайте» включено.
5. **Магазин и доставка**: блоки с отдельной кнопкой «Сохранить» у каждого или одной общей —
   «Доставка по Казахстану» (способы: название, цена ₸, срок; добавить/удалить способ; «бесплатно от, ₸»),
   «Доставка по миру» (текст), «Контакты» (WhatsApp, Instagram, Pinterest, e-mail, ссылка 2ГИС, адрес, часы работы),
   «Полоса сверху сайта» (текст на трёх языках), «Продавец» (ИП или ТОО с названием, ИИН/БИН — подсказка: «для подвала
   сайта, требуется законом для интернет-магазина»). Тексты на қаз/eng — свёрнуты.
