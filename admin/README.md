# Админка attré — для разработчика

Админка, в которой Дамира и Жанна сами ведут каталог: добавляют, меняют, скрывают и удаляют товары,
раскладывают фото по цветам, меняют цены, наличие, доставку и контакты. Работает с телефона.
Договорённости (формат данных, API, интерфейс) — в [DESIGN.md](DESIGN.md), инструкция для основательниц —
в [GUIDE.md](GUIDE.md).

## Как устроено

```
телефон / ноутбук ──► админка на Railway (этот каталог) ──► GitHub API ──► репозиторий daulet-rama/attre-site
                                                                             data/*.json + media/products/*.jpg
                                                                                   │ коммит в main
                                                                                   ▼
                                                     GitHub Actions (.github/workflows/pages.yml):
                                                     python build.py → GitHub Pages (сайт)
```

* Своих данных у админки нет: она читает и пишет файлы репозитория. Каждое «Сохранить» — один коммит в `main`
  (JSON и фото вместе), например `Админка: «Altea» — сохранено (Дамира)`. История и откат — в git.
* Сайт пересобирается сам после коммита, обычно за 2–3 минуты. Ход публикации админка берёт из GitHub Actions
  (`GET /api/status`) и показывает полосой под шапкой.
* Две стороны не мешают друг другу: правки `admin/**` не пересобирают сайт (`paths-ignore` в `pages.yml`),
  а сохранения товаров (`data/`, `media/`) не перезапускают админку (Watch Paths в Railway). Сменённые в админке
  пароли (`.admin/users.json` в корне репозитория) не делают ни того, ни другого: `.admin/**` тоже в `paths-ignore`.
* Хранилище переключается переменной `STORE`: `github` — GitHub REST и Git Data API (боевой режим),
  `local` — локальная рабочая копия и `git` CLI, коммиты без push (разработка и тесты).

```
admin/
├── app/              бэкенд на FastAPI
│   ├── main.py       маршруты /api/*, раздача static/
│   ├── config.py     переменные окружения: проверка при старте, понятная ошибка
│   ├── auth.py       вход, подписанная cookie, ограничение попыток
│   ├── passwords.py  пароли, сменённые в админке: .admin/users.json в репозитории сайта
│   ├── store.py      хранилище: LocalStore (папка + git) и GitHubStore (GitHub API)
│   ├── catalog.py    чтение, проверка и запись data/ в формате сайта
│   └── images.py     фото: JPEG / PNG / WEBP / HEIC → JPEG до 2000 px, превью 480 px
├── static/           фронт без сборки: index.html, app.js + js/*.js (ES-модули), app.css
├── tests/            pytest на LocalStore (+ заглушка GitHub API)
├── requirements.txt  прямые зависимости; requirements.lock — всё закреплено, его ставит образ;
│                     requirements-dev.txt — для тестов и запуска на своём компьютере
├── Dockerfile, .dockerignore, railway.json, .env.example, .gitignore
├── DESIGN.md         договор: устройство, формат данных, API, интерфейс
├── README.md         этот файл
└── GUIDE.md          инструкция для Дамиры и Жанны
```

Зависимости — в `requirements.txt` (его ведёт бэкенд), образ ставит закреплённый `requirements.lock`
(см. [Зависимости](#зависимости)). Python 3.12+; образ собирается на 3.12.16, поэтому код не должен опираться
на возможности 3.13–3.14 (например, на отложенное вычисление аннотаций).

## Запуск на своём компьютере (STORE=local)

Нужны Python 3.12+ и git. Админка делает коммиты в отдельную копию репозитория сайта и ничего не пушит.

```bash
cd admin
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt      # requirements.txt + pytest + python-dotenv (для --env-file)

# Отдельная копия сайта: в неё админка будет коммитить (в ту ветку, что в ней выбрана).
# Свою рабочую копию лучше не подставлять.
git clone https://github.com/daulet-rama/attre-site.git /tmp/attre-test
# ветка ещё не на GitHub — клонируйте свою копию: git clone ~/attre-site /tmp/attre-test && git -C /tmp/attre-test checkout <ветка>

cp .env.example .env
# в .env: STORE=local, LOCAL_REPO=/tmp/attre-test, ADMIN_USERS=Дамира:тест;Жанна:тест,
#         SESSION_SECRET=<вывод: python3 -c "import secrets; print(secrets.token_urlsafe(48))">
#         (локально пароль может быть коротким; в боевом режиме STORE=github — от 12 символов, иначе не стартует)

uvicorn app.main:app --reload --port 8000 --env-file .env
# → http://localhost:8000
```

`--env-file` читает `.env` через python-dotenv (он в `requirements-dev.txt`; в образе его нет — там переменные
задаёт Railway). Значения в `.env` — без кавычек. Если чего-то не хватает, админка не стартует
и пишет по-русски, какую переменную поправить. Автора коммитов LocalStore задаёт сам (имя из входа,
`admin@attre.local`), настраивать git в копии не нужно.

Посмотреть сайт, собранный из той же копии (с правками из админки):

```bash
cd /tmp/attre-test
ATTRE_BASE=/ ATTRE_ORIGIN=http://localhost:8001 python3 build.py && python3 -m http.server 8001 -d site
# в .env админки: SITE_URL=http://localhost:8001/v4/   (нужен Pillow — подойдёт python из .venv админки)
```

Коммиты админки: `git -C /tmp/attre-test log --oneline`. Начать заново: `git -C /tmp/attre-test reset --hard origin/main`.

**В Docker** (так же, как на Railway):

```bash
cd admin
docker build -t attre-admin .
docker run --rm -p 8000:8000 --env-file .env attre-admin
```

В образе нет git, поэтому там работает только `STORE=github`. Чтобы не трогать боевой сайт, создайте в GitHub
ветку `admin-test` от `main` и поставьте `GITHUB_BRANCH=admin-test`: сайт собирается только из `main`, поэтому
с тестовой ветки ничего не публикуется (и полоса публикации там ничего не покажет).

## Тесты

```bash
cd admin
pip install -r requirements-dev.txt      # requirements.txt + pytest
python -m pytest -q
```

Тесты работают на LocalStore во временных клонах репозитория сайта (нужен установленный `git`), GitHub
подменён заглушкой (`tests/fake_github.py`) — в сеть не ходят. Один раз за прогон делается неглубокий клон
текущей ветки (или `ATTRE_TEST_REPO`), фото в нём уменьшаются до 240px, фото главной не копируются; каждый тест
получает свою маленькую копию — хватает пары сотен мегабайт во временной папке. Данные в копии — настоящие, поэтому
имена фото тесты берут из файлов товаров, а товары старого формата (без `variants`) кладут сами
(`tests/legacy_products.json`, фикстура `legacy`).

На той же версии Python, что в образе (3.12), — в одноразовом контейнере (из корня обычного клона; репозиторий
подключается только для чтения, в нём ничего не появится):

```bash
docker run --rm -e PYTHONDONTWRITEBYTECODE=1 -v "$PWD":/repo:ro -w /repo/admin python:3.12.16-slim sh -c \
  "apt-get update -qq && apt-get install -y -qq git >/dev/null && git config --global --add safe.directory '*' \
   && pip install -q --root-user-action=ignore -r requirements.lock pytest==9.2.0 \
   && python -m pytest -q -p no:cacheprovider"
```

## Переменные окружения

Образец со всеми переменными — [.env.example](.env.example). Если обязательной переменной нет или она неверна,
админка не запускается и печатает в журнал, что поправить (секреты при этом не выводятся).

| имя | нужна | что | пример |
|---|---|---|---|
| `STORE` | да | `github` (боевой режим; по умолчанию) или `local` | `github` |
| `GITHUB_TOKEN` | для `github` | fine-grained токен на один репозиторий: Contents — Read and write, Actions — Read-only, Metadata — Read-only | секрет |
| `GITHUB_REPO` | для `github` | владелец/репозиторий | `daulet-rama/attre-site` |
| `GITHUB_BRANCH` | нет | ветка, по умолчанию `main` | `main` |
| `LOCAL_REPO` | для `local` | путь к рабочей копии репозитория сайта | `/tmp/attre-test` |
| `ADMIN_USERS` | да* | `Имя:пароль;Имя2:пароль2`; в пароле нельзя `;`, в имени — `:` и `;`. При `STORE=github` пароль — от 12 символов и не равен имени, иначе админка не стартует (за формой входа — токен с правом записи в репозиторий) | `Дамира:…;Жанна:…` |
| `ADMIN_PASSWORD` | да* | если `ADMIN_USERS` пуст — один общий пароль, имя «Админ» (те же требования) | секрет |
| `SESSION_SECRET` | да | 32+ случайных символа для подписи cookie — только сгенерированных (команда ниже), не придуманных: по `pepper_id` в публичном `.admin/users.json` догадку о нём можно проверить. При `STORE=github` заглушку (меньше 8 разных символов, вроде `xxxx…`) админка не примет | секрет |
| `PASSWORD_PEPPER` | нет | 32+ случайных символа (так же сгенерированных) — ключ к файлу сменённых паролей `.admin/users.json`. Не задан — ключ производный от `SESSION_SECRET` (тогда смена `SESSION_SECRET` сбрасывает и сменённые пароли). Поменять — сбросить сменённые пароли всем ([Пароли и пользователи](#пароли-и-пользователи)) | секрет или не задавать |
| `SITE_URL` | нет | адрес сайта (тема v4) со слешем на конце; по умолчанию собирается из `GITHUB_REPO` | `https://daulet-rama.github.io/attre-site/v4/` |
| `TMP_DIR` | нет | временные загрузки фото (24 ч) и кэш превью (14 дней) | `/tmp/attre-admin` |
| `PORT` | нет | порт; на Railway не задавать — он подставляет свой | `8000` |
| `TRUST_PROXY` | нет | откуда брать адрес посетителя для счётчика попыток входа: `railway` — из `X-Real-IP` (или первого адреса `X-Forwarded-For`), которые ставит прокси Railway; `0` — адрес соединения. По умолчанию: на Railway (есть `RAILWAY_ENVIRONMENT_NAME`) — `railway`, иначе `0` | не задавать |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | на Railway | сколько Railway ждёт старый контейнер при деплое; 60 — чтобы начатое сохранение успело дойти до GitHub | `60` |

\* нужна одна из двух.

Ключ для `SESSION_SECRET` (и пароли, если хочется случайных):

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"   # 64 символа — для SESSION_SECRET
python3 -c "import secrets; print(secrets.token_urlsafe(12))"   # 16 символов — пароль
```

## Деплой на Railway

Делается один раз, около получаса. Все настройки задаются в панели Railway (почему не через `railway.json` —
в разделе [Про railway.json](#про-railwayjson)).

### 0. Перед началом

1. В `main` уже должны быть палитра из 15 цветов и новый формат товаров (`variants`) — сейчас это ветка `colors` —
   и сама папка `admin/`. Админка читает и пишет только `main`.
2. GitHub Pages собирается из Actions: репозиторий → Settings → Pages → Build and deployment → Source:
   **GitHub Actions** (уже так, раз сайт открывается).
3. Репозиторий `attre-site` **публичный** (иначе бесплатный GitHub Pages не работает). Значит, всё, что попадает
   в git, видно всем: `.env`, токен и пароли туда класть нельзя.

### 1. Токен GitHub (fine-grained, только на attre-site)

1. github.com под `daulet-rama` → аватар справа сверху → **Settings** → внизу слева **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**.
2. **Token name**: `attre-admin (Railway)`. **Description**: «Админка attré: запись data/ и media/, статус публикации».
3. **Resource owner**: `daulet-rama`.
4. **Expiration**: самый долгий срок с датой окончания — **Custom**, дата через год. GitHub разрешает и
   «No expiration», но токен с датой безопаснее: если он утечёт, то сам перестанет работать. Сразу поставьте
   в календарь напоминание за две недели до этой даты — «продлить токен админки attré»
   (как продлить — [ниже](#токен-github-продление-и-замена)).
5. **Repository access**: **Only select repositories** → `daulet-rama/attre-site`.
6. **Permissions** → Repository permissions (в новом интерфейсе GitHub — кнопка **Add permissions** и поиск
   по названию):
   * **Contents** — **Read and write** (читать данные, делать коммиты);
   * **Actions** — **Read-only** (статус публикации);
   * **Metadata** — **Read-only** (обязательное, GitHub ставит сам).

   Остальное — No access.
7. **Generate token** → скопируйте значение (`github_pat_…`): GitHub показывает его один раз. Вставьте сразу
   в Railway (шаг 3, переменная `GITHUB_TOKEN`) и больше нигде не храните — ни в чатах, ни в заметках, ни в git.

### 2. Пароли и ключ подписи

* `SESSION_SECRET` — вывод `python3 -c "import secrets; print(secrets.token_urlsafe(48))"`. Только так — не
  придумывать: репозиторий публичный, и по файлу сменённых паролей догадку о ключе можно проверить.
* Стартовые пароли для Дамиры и Жанны — от 12 символов: латинские буквы, цифры, `-` и `_` (без `;`,
  пробелов и `#` — так их одинаково поймут Railway и `.env`). Передайте каждой лично, не в общем чате;
  телефон предложит сохранить пароль — пусть соглашаются. Потом каждая может сменить свой пароль сама в админке
  («Сменить пароль»). Вход запоминается (подробнее — в разделе [Пароли и пользователи](#пароли-и-пользователи)).

### 3. Railway

1. [railway.com](https://railway.com) → **Login** → **GitHub** (аккаунт `daulet-rama`). Тариф — **Hobby**
   ([стоимость](#стоимость)): на пробном (Trial) разовые 5 $, потом сервис остановится.
2. **New Project** → **Deploy from GitHub repo**. В первый раз Railway попросит установить своё GitHub-приложение:
   **Configure GitHub App** → **Only select repositories** → `attre-site` → Save.
3. Выберите `daulet-rama/attre-site`. Если Railway предложит **Add variables** — нажмите его, тогда первая сборка
   не начнётся впустую. Если сборка уже пошла из корня репозитория и упала — не страшно, это до настроек ниже.
4. Откройте карточку сервиса → **Settings**:
   * имя сервиса (сверху) — `attre-admin`: из него получится адрес;
   * **Source** → **Root Directory**: `admin`; ветка (Branch connected to production) — `main`;
   * **Build** → **Builder**: Dockerfile (Railway сам находит `admin/Dockerfile`; если стоит Railpack — переключите);
     **Watch Paths**: `/admin/**` (то же, что `admin/**`: шаблоны считаются от корня репозитория, даже при
     Root Directory) — без этого каждое сохранение товара перезапускало бы админку;
   * **Deploy** → **Custom Start Command** — пусто (команда — в Dockerfile); **Regions**: **EU West**
     (Amsterdam, Netherlands; в списке может называться «EU West Metal»), **1** реплика — ровно одна:
     очередь записи и счётчик попыток входа живут в памяти процесса; **Healthcheck Path**: `/api/health`
     (таймаут — по умолчанию); **Restart Policy**: **On Failure**, 10 попыток; **Serverless** (сон при простое) —
     выключено.
5. **Variables** → **Raw Editor** → вставьте и подставьте значения → **Update Variables**:

   ```
   STORE=github
   GITHUB_TOKEN=<токен из шага 1>
   GITHUB_REPO=daulet-rama/attre-site
   GITHUB_BRANCH=main
   ADMIN_USERS=Дамира:<пароль>;Жанна:<пароль>
   SESSION_SECRET=<строка из шага 2>
   SITE_URL=https://daulet-rama.github.io/attre-site/v4/
   RAILWAY_DEPLOYMENT_DRAINING_SECONDS=60
   ```

   `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` — сколько секунд Railway даёт старому контейнеру при деплое (по умолчанию —
   почти 0): uvicorn за это время (`--timeout-graceful-shutdown 50` в Dockerfile) доводит начатое сохранение до
   GitHub, а не обрывает его посередине. Если в панели есть поле Settings → Deploy → **Draining Seconds** — там
   то же самое. `PORT` не задавайте. Значения — без кавычек. По желанию у `GITHUB_TOKEN` и `SESSION_SECRET` в меню «⋮»
   выберите **Seal**: Railway перестанет показывать их значения в панели и API. Распечатать обратно нельзя,
   менять — только через «⋮» (не через Raw Editor); эти два значения и так меняются целиком. `ADMIN_USERS`
   лучше не запечатывать: чтобы сменить один пароль, пришлось бы заново вписывать и чужой. По желанию —
   `PASSWORD_PEPPER` (зачем — в разделе [Пароли и пользователи](#пароли-и-пользователи)); задавать сразу, до первой
   смены пароля в админке.
6. Railway копит изменения настроек и переменных — сверху появится кнопка **Deploy** (или «Apply changes»).
   Нажмите: сборка образа 2–4 минуты, затем деплой станет **Active**. Если новая версия не прошла проверку
   `/api/health`, Railway оставляет работать прежнюю.
7. **Settings** → **Networking** → **Public Networking** → **Generate Domain**. Если спросит порт — тот, что
   в журнале деплоя в строке `Uvicorn running on http://0.0.0.0:…` (Railway сам задаёт `PORT`, обычно 8080).
   Получится адрес вида `https://attre-admin-production.up.railway.app`; поддомен можно поправить карандашом.
   Это и есть ссылка на админку для Дамиры и Жанны — вместе с [GUIDE.md](GUIDE.md).

После этого любой push в `main`, который меняет `admin/**`, пересобирает и перезапускает админку сам.

### 4. Проверка, что всё работает

1. **Deployments** → последний деплой → **View logs**: есть `Uvicorn running on …`, а через несколько секунд —
   `хранилище github доступно, превью готовы` (токен и репозиторий в порядке; админка заранее готовит превью
   главных фото). Строка `хранилище недоступно: …` — проблема с токеном или репозиторием (текст подскажет какая),
   «Админка не запущена — проверьте переменные окружения» — не хватает переменных. Токена и паролей в журнале
   быть не должно.
2. `https://<адрес>/api/health` открывается с ответом 200.
3. `https://<адрес>/` → вход Дамирой → список товаров тот же, что на сайте; под шапкой «Всё сохранённое — уже на сайте ✓».
4. Пробное сохранение, невидимое на сайте: «+ Добавить товар» → название «Тест», любая категория, один цвет
   с одним фото, выключить «Показывать на сайте» → «Сохранить и опубликовать». Дальше:
   * в GitHub → Commits — коммит `Админка: новый товар «Тест» (Дамира)` с JSON и фото;
   * в GitHub → Actions — прогон `pages` по этому коммиту; полоса в админке — «Публикуем на сайт…»,
     через 2–3 минуты — «Всё сохранённое — уже на сайте ✓»;
   * затем удалите тестовый товар («Удалить товар») — ещё один коммит, фото удалятся им же.
5. Откройте сайт — на нём ничего не поменялось.
6. **Адрес посетителя для счётчика попыток входа.** Выйдите и введите один раз неверный пароль с телефона —
   по Wi-Fi, а потом через мобильный интернет. В журнале деплоя найдите строки `неудачный вход с …`: там должен быть
   публичный адрес телефона, и с Wi-Fi и мобильного интернета он разный. Если адрес вида `100.64.x.x`, `10.x.x.x`
   или у всех попыток один и тот же — это адрес узла Railway, а не посетителя: счётчик стал бы общим для всех,
   и кто угодно, вводя неверные пароли, закрывал бы вход и Дамире, и Жанне. Тогда поставьте `TRUST_PROXY=0`
   (адрес возьмётся у uvicorn — первый из `X-Forwarded-For`) и разберитесь, какие заголовки присылает прокси
   (Railway в 2026 году: `X-Real-IP` и `X-Forwarded-For`, оба ставит сам). Потом войдите с верным паролем:
   одна неудача из десяти разрешённых входу не мешает.

## Если «не публикуется» или не работает

Журнал: Railway → сервис → **Deployments** → деплой → **View logs** (или вкладка **Observability**). Каждый
неудачный ответ GitHub там записан строкой `GitHub <метод> <адрес> → <код> <сообщение GitHub>` — по коду
видно, в чём дело. Перезапуск без пересборки: Deployments → «⋮» у активного деплоя → **Restart**.

## Пароли и пользователи

Кто может войти — по-прежнему только имена из `ADMIN_USERS` (или «Админ» при `ADMIN_PASSWORD`). Пароли оттуда —
**стартовые**: ими входят, пока человек не сменил пароль сам.

* **Смена самой основательницей**: в шапке имя (на телефоне — кружок с буквой) → **«Сменить пароль»** → текущий
  пароль, новый (8–128 символов, без пробелов по краям, не равен имени и текущему) и ещё раз новый. Это устройство
  остаётся в админке (сервер сразу выдаёт ему новую cookie), а все прежние входы этого человека на других
  устройствах перестают действовать: в подписи cookie — отпечаток его пароля. Вход второй основательницы не
  меняется. Неверный текущий пароль («Текущий пароль не подошёл…») считается вместе с неудачными входами (10 за
  15 минут с адреса, дальше 429 и для входа, и для смены — в окне смены «Слишком много неудачных попыток ввести
  пароль…»).
  Шаги для основательниц — [GUIDE.md](GUIDE.md#сменить-пароль).
* **Где хранится**: в репозитории сайта, файл `.admin/users.json` — в корне, а не в `admin/` (правки `admin/**`
  перезапускают админку на Railway). Каждая смена — коммит `Админка: смена пароля (Дамира)` в `main`, только этот
  файл (он в белом списке `store.check_path`). `.admin/**` в `paths-ignore` у `pages.yml`, поэтому сайт из-за смены
  пароля не пересобирается, и полоса публикации её не ждёт. В файле на человека — соль, хеш и время смены
  (пароль из `ADMIN_USERS` туда не попадает вовсе):

  ```json
  {
    "pepper_id": "3f9c0a1b2c3d4e5f",
    "users": {
      "Дамира": {"salt": "<base64, 16 байт>", "hash": "<64 hex>", "changed": "2026-10-29T06:29:17+00:00"}
    }
  }
  ```

* **Почему это безопасно, хотя репозиторий публичный**: `hash = HMAC-SHA256(pepper, scrypt(пароль, salt, n=2^14,
  r=8, p=1, dklen=32))` (пароль — в Unicode NFC, UTF-8). `pepper` — секрет, которого в репозитории нет: переменная
  `PASSWORD_PEPPER`, а если она не задана — `HMAC-SHA256(SESSION_SECRET, "attre-admin password pepper v1")`. Без него
  по файлу нельзя проверить ни одной догадки о пароле — даже простой пароль по файлу не подобрать. `pepper_id` в
  файле — отпечаток ключа (`HMAC-SHA256(pepper, "id")`, первые 16 hex): по нему админка видит, тем ли ключом записан
  файл. Вычислить ключ по нему нельзя, но **проверить догадку о ключе — можно**: поэтому `SESSION_SECRET` и
  `PASSWORD_PEPPER` — только сгенерированные, случайные (на 64 случайных символа перебор безнадёжен), а заглушку вроде
  `xxxx…` админка при `STORE=github` не примет. Проверка пароля — за постоянное время (`hmac.compare_digest`).
* **Если ключ всё же узнали** (утёк `SESSION_SECRET`, а `PASSWORD_PEPPER` не задан или утёк тоже): сменённые
  пароли можно подбирать по файлу — медленно (scrypt: около 16 МБ памяти и десятков миллисекунд на попытку, соль у
  каждой записи своя), но простой пароль так найдут. Подделать вход по одному ключу нельзя: в отпечатке cookie у
  сменённого пароля, кроме его hash, ещё стартовый пароль из `ADMIN_USERS` (и `PASSWORD_PEPPER`, если задан) — их в
  репозитории нет, и стартовый пароль пришлось бы ещё угадать (как и до смены паролей в админке). Что делать: сгенерировать новые `SESSION_SECRET` и `PASSWORD_PEPPER` (это выкинет всех и сбросит
  сменённые пароли), поменять стартовые пароли в `ADMIN_USERS`, а основательницы потом сменят пароли заново.
* **Как админка читает файл**: сразу после запуска, сразу после своей записи и дальше не чаще раза в минуту, каждый
  раз спрашивая у GitHub свежую голову ветки, — правку на GitHub (например, сброс) она подхватывает в течение
  минуты. GitHub не ответил — вход по последней прочитанной версии. Если после запуска файл ещё ни разу не
  прочитался, админка ждёт GitHub: вход паролем и запросы уже вошедших отвечают «GitHub не отвечает…» (503) —
  ни стартовыми паролями, ни входами, выданными по ним до смены, сменённые не обойти. Записи для имён, которых нет в
  `ADMIN_USERS`, не действуют. В журнал пишется только «смена пароля: Дамира» — сами пароли нигде не логируются.
* **Другие устройства после смены**: их вход больше не действует, и окно входа говорит «Пароль сменили — войдите
  с новым паролем» (сервер отвечает 401 с `reason: "password"`: cookie наша, но отпечаток пароля уже другой). Если
  одна и та же основательница меняет пароль на двух устройствах одновременно, второе получает то же окно входа, а
  не «Текущий пароль не подошёл», и попытка не идёт в счётчик.
* **Забыла пароль — сброс одному человеку**: GitHub → `attre-site` → `.admin/users.json` → карандаш (**Edit**) →
  удалить её запись — от `"Дамира": {` до закрывающей `}` (и лишнюю запятую, чтобы JSON остался правильным) →
  **Commit changes** в `main`. Не позже чем через минуту для неё снова действует стартовый пароль из `ADMIN_USERS` —
  его и сообщите. Удалить весь файл — сброс всем сразу. Испорченный при правке JSON админка не использует целиком
  (все входят по стартовым паролям, в журнале предупреждение) — поправьте или удалите файл.
* **Сброс всем через переменные**: поменять `PASSWORD_PEPPER`, а если он не задан — `SESSION_SECRET`. Файл записан
  прежним ключом, `pepper_id` не совпадает — админка не использует файл целиком и пишет в журнал «файл паролей …
  записан с другим ключом». Смена `SESSION_SECRET` заодно выкидывает всех из админки. Следующая смена пароля в
  админке перезапишет файл новым ключом.
* **После сброса снова действует стартовый пароль** — и вместе с ним входы, выданные по нему до первой смены
  (если им нет 30 дней). Если стартовый пароль мог стать известен посторонним или пароль меняли из-за потерянного
  телефона — заодно поменяйте его в `ADMIN_USERS`: тогда не подойдут ни он, ни те входы.
* **`PASSWORD_PEPPER`** (необязательно, 32+ случайных символа, тем же способом, что `SESSION_SECRET`): нужен, если
  хочется менять `SESSION_SECRET` («выйти всем»), не сбрасывая сменённые пароли. Задавайте сразу, до первой смены
  пароля в админке: появление или смена `PASSWORD_PEPPER` позже — это тоже сброс всех сменённых паролей.
* **Стартовый пароль поменять**: Railway → сервис → **Variables** → `ADMIN_USERS` → поменять пароль у нужного имени
  → **Update Variables** → **Deploy**. Действует, только пока у человека нет записи в `.admin/users.json`
  (сменила сама — её пароль из файла, и `ADMIN_USERS` на него не влияет). Прежние входы, выданные по старому
  стартовому паролю, перестают действовать сами. Стартовый пароль — часть отпечатка в cookie и у сменённого пароля,
  поэтому человека с записью в файле это тоже выкинет со всех устройств: войти — своим (сменённым) паролем.
* **Выйти всем и везде** (например, есть сомнение, что ключ подписи утёк): поменяйте `SESSION_SECRET` —
  недействительными станут все cookie, войти придётся заново всем (без `PASSWORD_PEPPER` — по стартовым паролям,
  см. выше).
* **Добавить или убрать человека**: дописать `;Имя:пароль` в `ADMIN_USERS` или удалить запись. Имя видно
  на экране входа и в истории коммитов. Удалённое имя выходит само, а его запись в `.admin/users.json` перестаёт
  действовать — но **её нужно удалить и на GitHub** (как при сбросе пароля, см. выше): если это имя когда-нибудь
  снова появится в `ADMIN_USERS` (вернулся человек или пришёл новый с тем же именем), запись оживёт — подойдёт
  прежний личный пароль, а стартовый — нет. Сама админка чужие записи не стирает: временно урезанный `ADMIN_USERS`
  (например, на время проверки) не должен молча сбрасывать пароли остальным.
* Cookie живёт 30 дней и продлевается при заходе (если ей больше суток), но не дольше 90 дней от входа паролем:
  раз в три месяца пароль спросят снова — так скопированная или украденная cookie не работает бесконечно.
  Если не заходить дольше месяца, тоже спросят.

## Токен GitHub: продление и замена

* **До окончания срока**: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens →
  `attre-admin (Railway)` → **Regenerate token** → новый срок (снова через год) → скопировать новое значение →
  Railway → `GITHUB_TOKEN` → **Update Variables** → **Deploy**. Новое напоминание в календарь.
  GitHub обычно присылает письмо незадолго до окончания срока, но лучше не полагаться только на него.
* **Срок уже истёк** (админка перестала сохранять): истёкший токен не восстановить — создайте новый с теми же
  правами ([шаг 1](#1-токен-github-fine-grained-только-на-attre-site)) и замените `GITHUB_TOKEN`.
* **Токен мог утечь**: сразу удалите его на той же странице (Delete), выпустите новый и замените в Railway.
  Если токен случайно попадёт в публичный репозиторий, GitHub отзовёт его сам — админка перестанет сохранять,
  пока не будет нового.

## Своя ссылка (admin.attre.studio) — когда будет домен

1. Railway → сервис → **Settings** → **Networking** → **Custom Domain** → `admin.attre.studio`.
2. Railway покажет записи **CNAME** и **TXT** — добавьте обе в DNS у регистратора домена.
3. Подождать (от минут до нескольких часов), сертификат HTTPS Railway выпустит сам.
4. Старый адрес `*.up.railway.app` продолжит работать; на новом адресе основательницам нужно войти заново
   и заново добавить значок на экран «Домой».

Когда сайт переедет на свой домен, поменяйте `SITE_URL` (и адрес сборки сайта в `pages.yml` — это уже не админка).

* **Railway Hobby — около 5 $ в месяц**: подписка 5 $ включает 5 $ ресурсов, а админке (один небольшой контейнер,
  в покое 150–250 МБ памяти, почти без нагрузки на процессор) обычно хватает 1–3 $. Но пока обрабатывается
  большое фото, память на секунду-две поднимается до 0,5–1 ГБ (фото обрабатываются по одному; прогрессивный
  JPEG и всё, кроме обычного JPEG, — не больше 50 Мп). Если ставить лимит памяти сервиса — **не ниже 1,5 ГБ**:
  иначе контейнер убьют посреди загрузки, а вместе с ним пропадут счётчик попыток входа и незавершённые загрузки.
  Платится фактически использованная память, так что запас ничего не стоит. Сверх включённого Railway
  списывает по факту; лимит расходов можно поставить в настройках оплаты (Usage limits).
* **GitHub** — бесплатно: репозиторий публичный, Actions и Pages для публичных репозиториев бесплатны.
* Свой домен — отдельно, у регистратора.

## Где лежат данные и фото; история и откат

Всё — в репозитории `daulet-rama/attre-site`, у Railway только временные файлы. Несохранённые правки (черновики
форм) живут сутки в браузере того телефона или компьютера, где их вводили (localStorage, ключи
`attre-admin-draft:<адрес товара | new | settings>`) — на сервер они не уходят:

* товары — `data/products/<адрес>.json` (имя файла = адрес страницы, после создания не меняется);
* пароли, сменённые в админке, — `.admin/users.json` (соль и хеш, не сами пароли; см. «Пароли и пользователи»);
* доставка и контакты — `data/settings.json`; адрес, часы работы, полоса сверху и «доставка по миру» —
  ключи `address`, `hours`, `promo`, `dlv_world` в `data/i18n.json` (остальное админка не трогает);
* фото — `media/products/<адрес>-<цвет>-<6 hex>.jpg`: мастер-копии до 2000 px, JPEG q88. Размеры для сайта
  (3:4, WebP 600 и 1200 px) режет `build.py` при сборке. Фото, на которые больше не ссылается ни один товар,
  удаляются тем же коммитом, но остаются в истории git.

Тексты, где те же данные записаны прямо в `data/i18n.json` и админка их **не** меняет: `store_body` (адрес
в разделе «магазин» на странице товара), `wear_note` (ник Instagram на главной), `bonus_short`, `bonus_body`,
`wa_cart_bonus` (сумма бонуса 2 000 ₸; полоса `promo` при этом меняется из админки), `delivery_body` (запасной
текст доставки — показывается, только если в настройках нет ни одного способа). Если основательницы меняют
адрес, ник или условия бонуса — эти ключи поправить вручную (а лучше перевести их в теме на подстановки
вроде `{address}`).

**История**: GitHub → Commits — каждое сохранение подписано, что и кто: `Админка: «Altea» — сохранено (Дамира)`,
`Админка: удалён «Tokyo» (Жанна)`, `Админка: порядок товаров (…)`, `Админка: доставка и контакты (…)`.

**Откат** (сайт после push пересоберётся сам, админка увидит изменения):

```bash
git pull
git revert <sha>                     # отменить одно сохранение целиком — JSON и фото вместе
git push

# вернуть один товар к состоянию до коммита <sha>:
git checkout <sha>^ -- data/products/altea.json
git checkout <sha>^ -- media/products/altea-milky-3fa2c1.jpg   # и его фото, которые тот коммит удалил
git commit -m "Возврат «Altea» к версии до <sha>" && git push
```

Удалённый по ошибке товар возвращается `git revert` коммита `Админка: удалён «…»`. Резервная копия — любой
клон репозитория; можно время от времени делать `git clone --mirror`.

Репозиторий растёт с каждым новым фото (0,3–1 МБ на фото, старые версии остаются в истории). GitHub рекомендует
держать репозиторий до 1–5 ГБ, а опубликованный сайт Pages ограничен 1 ГБ — запаса на годы.

## Безопасность

* Токен GitHub — только в переменной окружения: в ответы API, логи и git не попадает. Права — один репозиторий,
  минимальный набор. Даже с ошибкой в коде админка пишет только `data/products/<адрес>.json`, `data/settings.json`,
  `data/i18n.json`, `media/products/*` и `.admin/users.json` (белый список в `store.check_path`) — не `build.py`,
  не `core.py`, не палитру и не главную.
* Вход: при `STORE=github` стартовые пароли — от 12 символов и не равны имени (иначе админка не стартует);
  сравниваются отпечатки SHA-256 через `hmac.compare_digest`. Сменённый в админке пароль (от 8 символов) — в
  публичном репозитории только как `HMAC-SHA256(pepper, scrypt(…))` с секретным pepper ([Пароли и
  пользователи](#пароли-и-пользователи)). После неверного пароля — пауза 1 с (без занятого потока); попытки
  проверяются по одной, так что одновременные запросы не обходят счётчик.
  Не больше 10 неудачных попыток за 15 минут с одного адреса (у IPv6 — с сети /64), а больше 30 неудач со всех
  адресов вместе — минута паузы для всех после каждой неудачи. Cookie подписана (itsdangerous), `HttpOnly`,
  `Secure` (кроме localhost и домашней сети), `SameSite=Lax`, 30 дней с продлением, но не дольше 90 дней от входа
  паролем; в подписи — отпечаток пароля (у сменённого — его хеша, стартового пароля и `PASSWORD_PEPPER`, чтобы
  по одному `SESSION_SECRET` и публичному файлу вход не подделать): любая смена пароля выкидывает прежние входы
  этого человека. Пока файл сменённых паролей после запуска не прочитан, по cookie тоже не пускают (503).
* Без действующей сессии запросы к `/api/*` (кроме `/api/health`, `/api/login`, `/api/logout`) получают 401 ещё
  до разбора тела; вход и смена пароля принимают тело не больше 4 КБ. Имена пользователей отдаёт только
  `GET /api/login`.
* Изменяющие запросы — только JSON (кроме загрузки фото) и с заголовком `X-Requested-With: attre-admin` (CSRF).
  Имена товаров, файлов и загрузок проверяются регулярными выражениями, размер запроса ограничен. Поля, которых нет
  в форме, но которые уже есть в файле (у цвета — `hex`, `pattern`, `published`), сохраняются, только если они
  правильные (`hex` — `#rrggbb`, `pattern` — узор из `core.PATTERNS`, `published` — да/нет, прочие — небольшие).
  Из текстов убираются управляющие символы, в том числе символы направления текста.
* Заголовки: `Content-Security-Policy` — скрипты, стили, запросы и формы только со своего адреса
  (`'unsafe-inline'` — только для стилей, `blob:` — превью фото с телефона); на https —
  `Strict-Transport-Security` (год); `X-Frame-Options: DENY`, `nosniff`, `noindex`; uvicorn не называет себя
  (`--no-server-header`).
* За прокси Railway uvicorn запущен с `--proxy-headers --forwarded-allow-ips="*"`: схема https берётся из
  заголовков прокси (снаружи до контейнера иначе как через прокси Railway не достучаться). Адрес для счётчика
  попыток входа (`auth.client_ip`) — `X-Real-IP`, а если его нет — первый адрес `X-Forwarded-For`: край Railway
  ставит оба сам и то, что прислал браузер, перезаписывает; последний адрес цепочки — узел Railway, общий для всех.
  Это включается только за прокси (`TRUST_PROXY`, на Railway — само); после деплоя адрес стоит проверить
  ([п. 6](#4-проверка-что-всё-работает)).
* Из фото при сохранении убираются EXIF (там бывает геопозиция).
* `.env` не коммитить (репозиторий публичный): он перечислен в `admin/.gitignore` и `admin/.dockerignore`.

## Про railway.json

`railway.json` записывает те же настройки, что задаются в панели: сборка по Dockerfile, Watch Paths `/admin/**`,
проверка `/api/health`, перезапуск при сбое (10 попыток), 60 секунд на завершение старого контейнера при деплое
(`drainingSeconds`; в панели — переменная `RAILWAY_DEPLOYMENT_DRAINING_SECONDS=60`), регион EU West, одна реплика. Но Railway объявил
«Config as Code» устаревшим: по документации (проверено 28.10.2026) новые сервисы его не читают вовсе, а у старых
файлы перестают читаться с 1 декабря 2026 года. Поэтому источник истины — **настройки в панели** (шаг 3 выше),
а файл — их запись в репозитории. Если понадобится описывать проект кодом, у Railway теперь Infrastructure as Code
(`.railway/railway.ts` и `railway config apply`) — переносить туда эти же настройки.

Если сервис когда-нибудь окажется «старым» (с Config as Code), путь к файлу нужно указывать от корня репозитория:
Settings → Config-as-code → `/admin/railway.json` — файл не следует за Root Directory.

## Зависимости

* `requirements.txt` — прямые зависимости с точными версиями: FastAPI, uvicorn (без `[standard]`: watchfiles
  и websockets в образе не нужны) с `httptools` и `uvloop`, httpx, Pillow, pillow-heif, itsdangerous,
  python-multipart.
* `requirements.lock` — всё, что ставит образ, вместе с зависимостями зависимостей (Starlette, pydantic, anyio, h11…):
  пересборка образа не подтянет новую мажорную версию Starlette незаметно. Получен в том же образе, на котором
  собирается админка:

  ```bash
  cd admin
  docker run --rm -v "$PWD":/admin -w /admin python:3.12.16-slim sh -c \
    "pip install -q --root-user-action=ignore -r requirements.txt && pip freeze" > /tmp/lock.txt
  # шапку-комментарий из старого requirements.lock перенести, остальное заменить содержимым /tmp/lock.txt
  ```

  Поменяли версию в `requirements.txt` — пересоберите lock этой командой и прогоните тесты на 3.12
  (команда — в разделе [Тесты](#тесты)).
* Базовый образ в `Dockerfile` закреплён версией и digest (`python:3.12.16-slim@sha256:…`): пересборка берёт ровно
  тот Python, на котором прогнаны тесты. Раз в несколько месяцев (обновления безопасности Debian и Python)
  обновляйте: свежий digest — `docker buildx imagetools inspect python:3.12-slim` (или страница тега на Docker Hub),
  поставить его и номер версии в `FROM`, прогнать тесты на этом образе.
* Хэши пакетов (`pip install --require-hashes`) пока не используются: для них нужен `pip-compile --generate-hashes`
  под Linux и Python 3.12; при желании — следующий шаг.
